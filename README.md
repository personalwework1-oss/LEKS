# LEKS — приватный мессенджер

Мессенджер для iPhone и Android без обязательного номера телефона, со сквозным шифрованием во всех чатах.

Спецификация версии 1: функции, архитектура, требования к качеству и план по этапам — в документе «Мессенджер: спецификация версии 1».

## Состав репозитория

| Папка | Что это | Технологии |
| --- | --- | --- |
| `crates/leks-crypto` | Ядро шифрования: ключи, группы, шифрование и расшифровка сообщений | Rust, OpenMLS (RFC 9420) |
| `packages/protocol` | Описание протокола между приложениями и сервером, общее для обеих сторон | TypeScript, zod |
| `apps/server` | Сервер: аккаунты, доставка сообщений, push-сигналы. Содержимое сообщений не видит | Node.js, Fastify, WebSocket, PostgreSQL |
| `apps/mobile` | Приложение для iOS и Android (появится на этапе 1) | React Native, Expo |

## Текущий этап

**Этап 0 — фундамент.** Критерий приёмки: зашифрованное сообщение проходит между двумя клиентами, а ядро шифрования собирается под iOS и Android. Проверяется автоматически в CI на каждый коммит.

## Запуск для разработки

Нужны Node.js 22, pnpm 10, Rust (stable) и Docker.

```sh
docker compose up -d                       # PostgreSQL и Redis
pnpm install
pnpm build
DATABASE_URL=postgres://leks:leks@localhost:5432/leks pnpm test
cargo test                                 # тесты ядра шифрования
DATABASE_URL=postgres://leks:leks@localhost:5432/leks pnpm dev:server
```

Сервер слушает порт 8080: `GET /health` — состояние, `/v1/ws` — WebSocket для приложений.

## Принципы

- Шифрование происходит только на устройствах. Сервер хранит и пересылает зашифрованные байты.
- Сервер не пишет в журналы IP-адреса, заголовки и тела запросов.
- Каждое изменение проходит автотесты в GitHub Actions; этап не закрывается, пока критерий приёмки не выполнен.
